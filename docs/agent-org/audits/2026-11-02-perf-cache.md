# Query Performance + Caching Audit — 2026-11-02

Scope: read-only audit repo `teknikalidnew` (Next.js 16 + Prisma + PostgreSQL docker `teknikalidnew-db-1`). DB sizes: **StockPrice 549.546 rows · StockIndicator 524.990 · Stock 1.451 · Article 168 · ForeignFlow 5.772 · Question 115**. EXPLAIN ANALYZE via psql (SELECT-only). Catatan: `pg_stat_user_tables.n_live_tup` = 0 (stats reset / VM terbatas) — row count di atas dari `COUNT(*)` langsung.

## Ringkasan

**14 temuan: 4 HIGH · 6 MED · 4 LOW.** Kondisi umum LEBIH BAIK dari dugaan: N+1 klasik (loop findUnique per item) sudah dimigrasi besar-besaran ke batch LATERAL raw SQL (fix-2026-10-26-11/12, ref-2026-10-17-01 "SATU PINTU"), breadth/movers sudah lewat `marketSnapshotService` cache 60s, indikator ter-indeks baik. Yang tersisa adalah: (a) backtest swing 24-bulan full-scan 886ms per regenerasi cache, (b) `findLatestDailyBrief`/`findLatestBriefMentioning` tanpa indeks partial yang mengenai `content ILIKE`-ish scan berkala, (c) sitemap per-jam men-trigger `groupBy max(date)` seq-scan 32ms + query likuiditas 30 hari yang semuanya bisa unstable_cache, (d) beberapa halaman anon yang data-nya identik per sesi tapi tetap force-dynamic penuh.

## EXPLAIN ANALYZE (3 terberat, dijalankan langsung)

1. **Backtest swing 24 bln** (`api/market/swing`): **885,8 ms** — Parallel Seq Scan StockIndicator 524.990 rows (13 rows tersaring), Parallel Hash Join StockPrice, temp written 1992 pages. → precompute EOD.
2. **Sitemap `groupBy stockId max(date)`**: **32,2 ms** — Parallel Seq Scan 549.546 rows ×3 workers + HashAggregate. → DISTINCT ON via index.
3. **Snapshot session LATERAL** (market-snapshot): **5,3 ms** (831 lateral loops index backward scan) + query likuiditas sitemap 30-hari: **7,7 ms** — sehat, biarkan.

## 3 Quick-Win Caching Terbesar

1. **`getYesterdayRecap` cache** (pasar off-hours): mayoritas trafik malam/weekend saat ini menjalankan fetch IHSG eksternal + 3 batch query per request. TTL sampai jam bursa berikut → menghapus ratusan query+fetch per jam.
2. **Precompute swing backtest per EOD** (worker pasca eod-sync): menghapus query 886ms dari rotasi 60s selamanya; cache route tinggal membaca hasil.
3. **Dedup `fetchStockBase` + cache detail ticker 60-120s**: `/stocks/[ticker]` adalah halaman termahal (±25-28 query); metadata+page double-fetch base yang sama — memoize per request + TTL pendek memotong ~7-8 query tiap pageview.
